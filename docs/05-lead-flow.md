# juece-grow · 线索流程（抖音/小红书/Chatwoot）

## 1. 线索来源分类

| 来源 | 入池方式 | 特点 |
|---|---|---|
| 网页表单 | Form 内嵌站点，提交自动生成 Lead | 结构化，自动打标 |
| 抖音 | 手动/API 入池 | 视频评论区、私信需人工转 |
| 小红书 | 手动/API 入池 | 图文评论、私信需人工转 |
| 微信 | 手动添加 | 加好友后录线索 |

## 2. 统一线索池与去重

- 所有线索落同一张 `leads` 表，字段带 `projectId`、`sourceId`。
- 去重指纹 `dedupKey`：优先手机号，其次微信；同指纹自动标记重复，可合并。
- 同一人从抖音和小红书各来一次，合并成一个 Lead，保留最近来源。

## 3. Chatwoot 收件箱

- Chatwoot 作统一收件箱，接客服对话。
- 通过 Chatwoot API 通道接入：网页 live chat、可扩展 API channel。
- 对话产生有效线索时，写回自有 PostgreSQL `leads`，不是存在 Chatwoot 里。
- 目的：客服在统一界面响应，业务数据仍由自己掌控。

## 4. 线索生命周期

```
new(新线索) → contacted(已联系) → won(成交)
         \                 \
          └(无效)→ closed(关闭)

每步记录 LeadActivity: 谁、何时、做了什么、备注
分配: new 线索按规则分配给 assignee
```

## 5. 打标与归因

- 每个 Lead 记录来源(sourceId)、渠道；可回溯到具体活动/文章。
- 后台按项目+来源+时间统计：哪个渠道带来多少有效线索、成交情况。
- 便于判断抖音、小红书、SEO、表单各渠道投入产出。

## 6. 手动转线索流程（抖音/小红书）

1. 运营在抖音/小红书看到咨询 → 复制关键信息。
2. 后台「新建线索」选来源=抖音/小红书，填手机号/微信。
3. 系统按 dedupKey 自动提示是否已存在 → 可选并入。
4. 归入项目，分配跟进人。

## 7. 红线
- 线索主数据只存在自有 PostgreSQL，不依赖 Chatwoot 或任何 SaaS 的库。
- 不批量爬取抖音/小红书（遵守平台规则），以人工/官方能力入池为主。
